# Browser world rendering

The renderer displays all 32 supplied village rooms using the original `.room` layouts, MilkShape ASCII models, and TIM2 texture atlases. This includes the rooms adjoining the initial five-room preview, so crossing into another supplied room keeps its scenery visible. It has orbit, zoom, pan, room focus, a character close-up, and a ground-shadow toggle. With the Pike server and gateway running, it also signs in and reads live character positions.

## Build the assets and start the viewer

From the project root in PowerShell:

```powershell
wsl -d Ubuntu -- python3 tools/build_browser_assets.py
wsl -d Ubuntu -- sh tools/node-env.sh npm ci --prefix browser
wsl -d Ubuntu -- sh tools/node-env.sh npm run dev --prefix browser
```

Open `http://127.0.0.1:5173/`. The development server remains available while the last command is running. For a production bundle, run `wsl -d Ubuntu -- sh tools/node-env.sh npm run build --prefix browser`.

The converter reads the ignored `Server/` snapshot and writes generated browser assets to the ignored `browser/public/assets/` directory. It supports the 8-bit indexed TIM2 variant used by these rooms: the files carry 256-color palettes and upload their pixel data as 32-bit GS transfers. The script restores linear 8-bit indices, reads the palette, and writes RGBA PNG. It writes static `.gltf` geometry with positions, normals, and UVs. Room placement stays in `scene.json` so model instances can share geometry. It converts all 150 supplied models, 12 textures, and 19 animation definitions. The ghost animation's `-1` part count is a special case in the original client. The viewer loops the saved animation samples for the preview character and briefly plays them when Pike reports movement.

The converter discovers every `village*.room` file in the supplied source. The generated scene currently contains 178 room objects. Room art and the preview character load together at startup; the remaining converted art loads only when Pike announces a monster, item, spell, or appearance change. Objects declared without a static `003 LOCATE` are hidden until Pike supplies their position, avoiding chess pieces and a rope appearing at the world origin. The named camera-focus buttons include the river crossing; the other rooms are visible while walking or orbiting.

The original PS2 texture loader overwrote the palette alpha on ordinary textures. Some supplied atlases, including `fluids8_.tm2`, have zero alpha in every stored palette entry, so copying that alpha made the river invisible. The converter now writes those atlas pixels opaque and lets the renderer apply transparency to water meshes. Original `U*` water models also scroll their texture coordinates; the browser repeats their quarter-atlas V movement.

`tools/check_window_texture.py` compares the converted `window_.tm2` with the supplied `Server/resource/window.bmp` reference. The direct palette interpretation matches all 65,536 RGB pixels. The model exporter checks triangle winding against the saved normals, which avoids alternating dark faces in Three.js.

The room files include `T*` meshes with a `009 BIAS` that lifts them slightly above the ground. Most are shadow polygons whose UVs sample the empty corner of `window_.tm2`; the viewer gives those a subtle dark material. `Tchurch.txt` also contains stained-glass windows and colored floor projections. The renderer separates its unpainted shadow triangles from its mapped glass and projection triangles, places each floor triangle just above its original surface (the main church floor is at height 0 and the blue rear floor at height 1), and places a dark layer beneath the colored projections. This keeps the wall shadow continuous through the spaces between windows and through transparent parts of their projections without cutting through pillar bases. The window atlas has no usable palette alpha, so its near-black palette index 0 is treated as empty space. The stained glass is slightly transparent, while the floor projections use their own softer opacity. The shadow toggle affects the dark polygons while leaving the glass visible. These blend choices are an interpretation of the original assets, not a verified reproduction of the PS2 blend.

The daylight uses a strong directional light with modest hemisphere fill. This leaves the sides facing away from the sun substantially darker, closer to the supplied PS2 reference. It changes surface shading; the renderer still does not compute real-time cast shadows from every object.

The live client responds to Pike's `024 LIGHT` with the original quarter-strength ambient/directional setting for dark areas. It also follows the nearest `025 PLON BLOB` source (a carried lit stick or torch, or a spell) with a warm point light four world units above that actor, uses `PLON PLACE` for a dropped light, accepts `PLCOLOUR`, and turns the light off on `PLOFF`. The fixed ground-shadow polygons fade locally around an active point light, matching the lit-stick reference where the building shadow gives way to illuminated ground; they return to their original opacity when the light goes out. Both falloffs are visual approximations of the PS2 shader.

The church clock hands, elevator, and three doors use their original models. The offline preview starts the elevator and doors at the initial coordinates from `village501501.pike:get_update()`. During play, Pike's `003 LOCATE` and `019 ROTATE` messages place and rotate those objects; the elevator moves over the script's eight-second travel interval, and the doors slide briefly. Pike's `007` interaction prompt becomes an Interact button and F-key action, which sends the original `trigger` command.

The live game panel keeps the latest 60 Pike `008` text messages in a scrollable log, shows hit and spell points from `012`/`020` and the `score` response, and requests the original `inventory`, `score`, and `who` lists on demand. The list is rendered as plain text from `016` responses; the browser does not maintain a separate inventory or character state.

Pike's `021 SELECT` opens a scrollable reading panel and subsequent `016 TXT` lines fill it, preserving blank lines and indentation. This displays the adventurers' stone inscription, message board, pub rules, and similar room text sent by the original server. Close dismisses the panel locally, like leaving SELECT mode on the PS2.

The 3D stage and its screen overlay are fixed to the viewport. Opening a list or shop panel changes the document height without resizing the WebGL canvas, which avoids a visible flash and camera aspect change.

When Pike sends `007 shop`, the browser offers a Shop button in the game panel. In the PS2-style controller command mode, SELECT then Circle opens the shop list, and Circle buys the selected item. Buy requests Pike's `list` and displays its `016 BUY` rows; Sell requests `inventory` and displays its `016 INV` rows. Choosing an item sends Pike's original `buy` or `sell` command and refreshes the list after a successful transaction. `006` removes the shop option. The pub's `007 buy drink` is a separate room trigger: Square activates it directly while standing at the bar.

Live `001 NAME` messages create players, monsters, items, and spell objects with the model and texture Pike specifies. An arriving `003 LOCATE` is retained while an asset downloads, so the object appears at its server position when ready. `014 UPDATE` and `018 CUPDATE` replace entity parts or changed scenery, including equipment and river/safe states. `015 REMOVE` deletes dynamic objects; reconnecting restores the offline scenery. Unknown resource names are reported in the browser console.

Magic missile uses the original `spell <direction>` command from Circle/B during play, C, or the Magic missile button. The browser preloads `spell.txt` and `items8_.tm2`, keeps the projectile's first `003 LOCATE` as its launch position while the model loads, follows `022 SPEED 3` at about 18 world units per second on each axis, and spins it for `017 ROTATEY`. Pike's point light follows the visible projectile. Pike still decides level, spell points, targets, damage, and removal.

The browser's current controls use W/S (or up/down arrows) for movement. Before the player turns, W moves into the camera view and S toward the viewer. After the first Q/E turn, W follows the character's facing and S steps backward without reversing the character's facing. Q/E continue turning the character in 45-degree steps (Q visually counterclockwise, E clockwise), including while W/S are held. A/D and the left/right arrow buttons are disabled while the control scheme is being refined. An overhead view retains the last horizontal camera direction. F activates an available room interaction. Space or the Attack button attacks one grid step in the character's current facing, with Pike deciding hits, misses, and the one-second cooldown. Pike still authorizes every grid step. The original PS2 client used `RELATIVE_MOVES` to rotate pad movement by the camera segment. The original `FIXED_CAMERA` build followed the player from above (30 units) and one of eight horizontal viewpoints, with the default viewpoint 20 units south; R3 selected a viewpoint from the player's facing. The browser begins at that default viewpoint, follows the player without resetting an angle chosen by dragging, and reserves the interaction button's space so `007`/`006` prompts do not resize the scene while walking. The PS2 examine mode temporarily moved toward a server-supplied `004 CAMERA` viewpoint and restored the old view on release. In the browser, hold X for the same temporary view, or toggle the Examine button when using mouse or touch.

Standard-mapped browser gamepads now support eight-direction movement on the left stick or D-pad, camera orbit on the right stick, L2/R2 character turns, L1 held examine, Cross/A attack, Square/X interaction, and R3 camera recentering. The left stick's horizontal direction follows the original PS2 client: a rightward push selects west from the default southern camera angle, so the character moves right on screen. L2 turns left and R2 turns right. Select/Back opens the original command mode: Cross/A shows Players, Square/X Inventory, Triangle/Y Character, and Circle/B opens the shop when one is nearby. In the shop list, the left stick or D-pad selects an item and Circle/B buys it. Start/Menu retains browser button navigation as an alternative. Analog input has a dead zone, menu actions use press edges, and controller movement stops when the tab loses focus or the pad disconnects. The browser shows the connection state and mapping beside the on-screen controls. Physical feel and controller-specific button labeling still need device testing.

The elevator platform model's top is at local height 0 and Pike places it at height 1 on the church's raised rear floor. The first-floor door is also placed at height 1. These match the original model and room script, so the visible placement gap has not been adjusted without a reference showing a different intended alignment.

Character movement follows the original client's timing: Pike accepts or blocks each grid step, and the browser moves a visible character toward each accepted `003 LOCATE` target at about 0.1 world units per 60 Hz frame. Holding an arrow key or WASD repeats move requests at most every ten 60 Hz frames, with one request outstanding at a time. A blocked `997` reply leaves the character at the last accepted position.

The pebble path uses the original atlas and model UVs. Its clearer browser appearance comes from the higher display resolution and modern texture sampling; the converter did not replace or upscale the artwork.

The pine meshes (`pine.txt` and `d123pine.txt`) may be third-party art, according to the creator. Their provenance and redistribution rights need review before publishing converted assets. Both the legacy source and generated browser assets remain ignored by Git.

Current limits: the browser displays the 32 supplied village rooms and dynamic objects using the supplied resources. Pike still decides collision and movement; the browser reports blocked steps. Audio, additional animation commands, and visual tuning against actual PS2 output remain. The preview uses a modern orbit camera and approximate lighting, so it is not yet a claim of frame-for-frame PS2 fidelity.
